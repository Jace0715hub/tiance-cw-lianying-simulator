“当前最优”只表示下列有界搜索中未找到更高结果，不表示对完整动作空间作出数学全局最优证明。

## 尚未证明的空间

- 束搜索在早期剪枝前未保留的动作祖先；现有核心候选之间相关性较高，不能代表全部合法结构。
- 仍可能存在未被现有有界模板或束宽召回的合法祖先，但当前持久化候选池中已没有尚未消费的0.1%内真实状态差异来源。
- 三个以上雷区段同时重构，以及多个雷/橙武/任驰骋锚点超过现有窗口的联合漂移。
- 现有搜索器会统计每层被束宽裁剪的状态，但尚未将其中少量高潜候选作为独立祖先续跑至180秒终局。
- 雷、橙武、断魂刺和下马目前主要覆盖GCD起点与末端两个时点；除突以外，尚未按冷却转好、增益消失等事件断点系统枚举GCD内时间。
- 完整180秒全状态A*、无界穷举或可证明的伤害上界，因此不能宣称全局最优。
- 随机延迟、未知战斗结束时间、240–600秒、非默认配装和非斩杀比例；这些属于后续环境维度，不用于当前180秒金标准选优。
- 尚未搜索两个以上短等待在不减少主要技能时的联合作用，也未将等待与后续雷区段重合成联合搜索。
- 尚未被用户或游戏实测确认、且伤害公式来源只经过Excel反推的机制误差。

## 下一候选生成优先级

1. 主线保持180秒。先在16帧总截止余量内搜索两个锚点短等待的联合，再对入选等待轴重合成末三雷区段，验证是否能在多一跳流血之外继续提高技能伤害。
2. 随后保存每个关键行/雷边界中被裁剪的少量高潜状态，将其作为独立祖先，用小束宽直接续跑到180秒。若能产生新的1%内完整轴，再以三至五个雷区段进行大邻域修复。
3. 240秒screen结果作为旁支基线保留，在180秒阶段由用户确认收口前，不继续生成300–600秒轴。

## 可复现实验入口

- `npm test`：机制与搜索回归测试。
- `npm run optimize:multisegments`：固定雷表连续区段搜索。
- `npm run optimize:anchor-coordinator`：层次化雷锚点协调。
- `npm run optimize:block-recombination`：从协调核心候选移植两雷动作块。
- `npm run optimize:compound-neighborhood`：正式轴上的通用双变换复合邻域。
- `npm run optimize:quality-diversity-restart -- /tmp/result [seed]`：固定束宽的状态质量—多样性重启。
- `npm run optimize:quality-diversity-tenure -- /tmp/result [seed]`：固定束宽、两雷区段有限祖先存活的对照实验。
- `npm run optimize:counterfactual-anchors -- - /tmp/result.json probe [rows]`：指定行主技能反事实筛选；`rows`为可选逗号分隔行号。
- `npm run optimize:counterfactual-windows -- - /tmp/result.json probe [start-end,...] [sequence|counts|both] [companionSlack]`：固定前缀的短窗口结构筛选；最后一项可选伴随锚点松弛行数。
- `npm run optimize:segment-skeletons -- - /tmp/result.json probe [limit] [offset] [warmReport]`：第3至第5雷区段计数骨架筛选；可用上一轮报告按模板ID显式热启动加宽复核。
- `npm run optimize:double-segment-skeletons -- - /tmp/result.json probe reportA,reportB [limit] [offset]`：从进入1%门槛的单骨架报告生成、去重并搜索有限双计数模板。
- `npm run optimize:anchor-count-skeletons -- - /tmp/result.json probe reportA,reportB [limit] [anchorOrdinal] [targetRow]`：将正式雷表单计数增量映射到不同雷表的真实区段边界后搜索。
- `npm run optimize:charge-count-skeletons -- - /tmp/result.json probe [limit] [offset]`：搜索统计完整动作包的断魂刺区段计数骨架。
- `npm run optimize:anchor-charge-count-skeletons -- - /tmp/result.json probe chargeReport [limit] [anchorOrdinal] [targetRow]`：把进入门槛的断魂刺计数增量映射到另一雷表的真实边界。
- `npm run optimize:difference-lineages -- - /tmp/result.json [probe|screen] [action|state]`：在相同束宽下对照默认选择器与动作差异或相对状态偏差谱系。
- `npm run optimize:triple-segment-recombination -- - /tmp/result.json [probe|screen|adaptive-probe] [donorReport] [donorId] [warmReport]`：从近优完整轴提取真实差异，联合搜索三个雷区段；不同雷表只开放正式与供体雷位置之间的有界窗口。
- `npm run optimize:multi-source-recombination -- - /tmp/result.json [probe|screen|adaptive-probe] [sourceReport] [sourceIds] [warmReports]`：合并非冲突来源差异，逐档钉住完整精英轴并搜索差异并集覆盖的三个雷区段。
- `npm run search:duration -- input.json /tmp/result.json duration [probe|screen]`：以已有完整轴为逐层钉住热启动，生成更长固定时长轴并报告原时长前缀得失。
- `npm run optimize:best-first-block -- - /tmp/result.json [probe|screen] [startRow] [endRow] [雷序号] [目标行]`：可选先移动一个雷锚点，再以变换后轴为基线，在固定锚点局部块中同预算对照逐层束与最佳优先队列。
- `npm run optimize:ride-thunder-templates -- - /tmp/result.json [probe|screen]`：固定雷与橙武，用离散任驰骋行表比较唯一单雷归属；不会把远距离移动展开成全行窗口。
- `npm run report:ranking-sensitivity`：正式轴与最近近优轴的事件/Excel分项排序核查。
- `npm run report:structure`与`npm run report:anchors`：只读结构和锚点审计。
