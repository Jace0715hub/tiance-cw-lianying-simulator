# 开发路线

## 项目目标与执行原则

- 唯一主目标是在已确认机制、默认5段加速配装和180秒斩杀木桩环境下，找到并完整复演验证更高DPS的橙武连营技能轴。当前正式比较指标为完整180秒含突循环伤害；装备期望伤害单列，不把报表丰富度或工具完整度当作项目成果。
- 开发优先级固定为：可能改变候选排序的机制/伤害正确性 → 能打开新技能轴结构的搜索动作与高层锚点 → 能保留长期高价值分支的剪枝改进 → 只读诊断和导出。后两项必须服务于前两项。
- 新工具只有在满足至少一项时才开发：能够搜索现有动作空间未覆盖的结构；能够修复已有遥测证明的剪枝盲点；能够对新优解执行必要的完整合法性复验。单纯改善接口、报表、通用性或代码外观不进入近期路线。
- 所有搜索分支使用有界预算和不降级回退。`screen`无正收益则停止同类扩档；出现正收益才升级`fast/balanced`，并最终与当前全局最优比较。局部候选、粗评分或工具完成本身不构成阶段成功。
- 近期重心继续放在180秒最高DPS搜索；M5.4已通过后段资源链、锚点联合重合成与通用机械邻域收敛，把总DPS提高到 `14,696,179.73`。结构种子生成和首轮跨雷坐标桥接已经完成，下一直接目标是从尚未收敛回当前轴的坐标谱系中选择新窗口，并提高“保持结构差异”的终局召回能力；M6以后功能、长时轴、配装器集成和非必要工程化仍暂缓。

## M0：机制规格与配置（已完成首版）

- 整数帧时间。
- 橙武、连营、龙驭结算顺序。
- 可配置 GCD、读条、CD和充能恢复模式。
- 独立 damage oracle 边界。

- 已将连续时钟合入完整状态转移，GCD、增益、冷却和顺序充能均使用统一刻度。

- 当前唯一明确的状态近似是“神兵·无双”按满层6675无双直接计入固定面板，没有模拟入战后的逐次命中叠层和6秒续期。它主要影响开场短窗口；先做已知高质量轴排序敏感性对照，只有确认会改变候选名次时才升级为动态状态，避免为几乎恒定的战斗内满层效果扩张主状态空间。
- 随机延迟、未命中、目标不可选中和转火不属于M1遗留开发，分别留在M6或未来战斗环境层；当前180秒确定性木桩最优轴搜索不等待这些功能。

## M3：原生伤害引擎与 Excel 离线验证（基本完成，保留一次排序风险核查）

- Excel 拆解结果只生成测试用 golden case，不参与运行时。
- 180秒基准技能表快照同样只供测试读取；重放器本身不依赖快照文件。
- 已完成自动攻击单次伤害、加速系数与周期调度，并接入统一伤害明细。
- 已将原连营和橙武牧云的基准技能数完全对齐，并提供逐技能总伤害差异报告。
- 五类装备触发的期望次数和伤害已与原配装器逐项一致。
- 当前连营基准总伤害相对Excel为`+838,713.94`（`+0.0377%`），牧云大橙武为`+9,522,347.01`（`+0.3949%`），均通过既有`0.5%`门槛。但连营总误差包含龙牙`-5,598,276.89`、破军`+7,779,765.65`、两类流血合计约`-2,067,854.20`等分项抵消，不能仅凭总误差断言所有近优轴排序完全一致。
- M3剩余工作限定为一次有界排序敏感性核查：选当前最优和少量最近候选，分别按现有事件模型与Excel分项口径复评，观察名次是否变化。若名次稳定，关闭M3并继续搜索；若变化，再只修正造成翻转的机制或权重。不会为追求逐项小数完全一致而长期打磨Excel兼容层。
